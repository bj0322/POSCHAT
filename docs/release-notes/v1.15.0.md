# POSCHAT 1.15.0 — 브라우저 멈춤 수정, POSCHAT Code

## 브라우저를 열면 앱이 "응답 없음"이 되던 문제(B1) 수정
- **원인**: 웹페이지 뷰의 네이티브 이벤트(WebView2 `NavigationStarting`·`SourceChanged`·`DocumentTitleChanged`·`NavigationCompleted`,
  WKWebView 내비게이션 대리자)는 UI 스레드에서 돕니다. 이 처리기가 주소·제목을 화면에 알리려고 `Bridge._push()` →
  `window.evaluate_js()`를 불렀는데, pywebview의 `evaluate_js`는 스크립트를 UI 스레드에 맡기고 결과를 기다립니다.
  결과를 넘겨줄 UI 스레드가 바로 기다리는 자기 자신이라 영원히 멈췄습니다(교착).
- **고친 방식**: `Bridge._push()`는 이제 이벤트를 큐에 넣고 바로 돌아옵니다(`ui_events.EventPump`). 전용 스레드 하나가 순서대로
  `evaluate_js`를 부릅니다. 연달아 온 같은 종류의 상태 이벤트(브라우저 주소·제목, 스트리밍 중간 답변, 녹음 소리 크기)만
  마지막 것으로 합치고, 다른 이벤트(메시지·승인 요청·PO노트 전사·차단 알림 등)는 하나도 버리거나 순서를 바꾸지 않습니다.
  큐에는 상한이 있고(화면이 멈춰도 메모리가 끝없이 늘지 않음), 보내다 난 오류는 그 이벤트만 실패로 셉니다. 앱 창이 닫히면 큐를 멈춥니다.
- PO노트·연구·에이전트 진행 표시 등 모든 화면 이벤트가 같은 길을 쓰므로 함께 막히지 않습니다.
- **확인**: CI의 실제 Windows(WebView2)·macOS(WKWebView) 창에서 열기·링크 이동·뒤로·앞으로·새로 고침·빠른 연속 이동·차단 주소·
  이벤트 폭주(제목 300번·주소 100번 바뀜)·불러오는 중 닫기·다시 열기를 하며 단계마다 앱 창이 5초 안에 응답하는지 봅니다.
  같은 시험을 예전 방식(`--legacy-push`)으로 돌리면 Windows에서 앱 창이 멈추는 것(교착 재현)도 기록합니다.

## POSCHAT Code (새 기능)
왼쪽 사이드바의 **코드**를 누르면 채팅 오른쪽에 코드 화면이 열립니다(논문·브라우저와 같은 자리, 서로 바꿔도 열린 탭과 저장하지 않은 내용은 남습니다).

- **파일 트리**: 작업 폴더를 한 단계씩 펼쳐 봅니다. 최근 파일, Git 변경 표시(M·?·U), 숨김 파일 보기, 이름·내용 찾기,
  새 파일·폴더, 이름 바꾸기, 지우기(데이터 폴더의 휴지통 `code-trash`로 옮김). `.git`·`node_modules`·`.venv`·`__pycache__`·`build` 같은 큰 폴더는 기본으로 빼고, 설정에서 바꿉니다.
- **편집기**(CodeMirror 6, 앱 안에 들어 있어 인터넷 없이 동작): 문법 강조, 줄 번호, 자동 들여쓰기, 괄호 짝, 찾기·바꾸기(Ctrl+F),
  되돌리기·다시 하기, 여러 파일 탭, 저장하지 않음 표시, 저장(Ctrl+S), 긴 줄 접어 보기, 밝은·어두운 테마.
  - 문법 트리 강조: Python, C, C++, JavaScript, TypeScript(JSX·TSX), JSON, Markdown, HTML, CSS.
  - 줄 단위 강조(키워드·주석·문자열·숫자, 접기·구조 인식 없음): Verilog, SystemVerilog(IEEE 1800 키워드), Tcl, Shell.
  - SPICE 넷리스트: 주석·점 명령·소자 이름·단위 붙은 숫자만 간단히. 그 밖은 일반 텍스트.
- **안전한 저장**: 같은 폴더의 임시 파일에 쓰고 한 번에 바꿉니다(저장 도중 실패해도 원본 유지). UTF-8·BOM·CP949·UTF-16,
  줄 끝(LF·CRLF), 마지막 줄 바꿈, 파일 권한을 그대로 둡니다. 연 뒤에 다른 프로그램이나 에이전트가 파일을 바꿨으면 조용히 덮어쓰지 않고
  '덮어쓰기 / 디스크 내용으로 다시 열기'를 묻습니다. 1MB가 넘는 파일은 읽기 전용, 8MB가 넘는 파일과 바이너리는 열지 않습니다.
  저장하지 않은 내용은 이 기기 화면 저장소에 잠깐 보관해, 앱이 갑자기 닫혀도 다음에 열 때 되살릴 수 있습니다(파일에 자동 저장하지 않음).
- **AI에게 묻기**: 선택한 부분(앞뒤 15줄 맥락 포함)·현재 함수/블록·파일 전체·관련 파일(최대 6개)을 파일 경로·언어·줄 범위와 함께 채팅에 첨부합니다.
  코드 설명·오류 분석·성능 개선·리팩터링 제안·주석 생성·테스트 코드 제안·RTL 로직 검토. 작업 폴더 전체를 보내지 않습니다.
- **에이전트 변경 검토**: Code 화면이 열려 있을 때 에이전트가 `write`/`edit`로 파일을 고치면, 승인 창 대신 **변경 검토**에 제안이 뜹니다.
  덩어리(hunk)마다 받아들이거나 빼고 '고른 변경 적용', '모두 적용', '모두 거부', '고쳐서 적용'을 고릅니다. 받아들이기 전에는 파일에 쓰지 않습니다.
  검토하는 사이에 파일이 바뀌면 충돌로 표시하고, '현재 파일에 맞춰 적용'은 덩어리 앞뒤 문맥이 그대로일 때만 합니다. 같은 제안은 두 번 적용되지 않습니다.
  에이전트는 일부만 적용됐는지, 고쳐서 적용됐는지를 알고 다음 단계를 정합니다. Code 화면을 닫으면 대기 중인 제안은 예전 승인 창으로 넘어갑니다.
- **Git**: 가지·앞섬/뒤처짐, 충돌·스테이지됨·바뀜·새 파일 목록, 파일별 차이(스테이지됨·작업 폴더 구분), 고른 파일만 스테이지/취소,
  스테이지한 변경만 커밋(확인 창, 저장소 커밋 훅이 있으면 이름을 보이고 끌 수 있음). AI에게 변경 설명·코드 리뷰·커밋 메시지 제안을 요청합니다.
  푸시·reset·clean·checkout은 없습니다. 받은 저장소의 `.git/config`에 적힌 filter·textconv·gpg 프로그램은 실행하지 않습니다.
- **실행 패널**: 작업 폴더에서 명령을 실행하고 출력을 실시간으로 봅니다(Windows cmd, macOS·Linux `/bin/sh`). 실행할 때마다 승인 창에
  명령·작업 폴더·네트워크 사용 가능성·위험할 수 있는 동작(rm -rf, git reset --hard 등)을 보이고, "작업 폴더는 격리가 아니다"를 알립니다.
  종료 코드·실행 시간·중지·기록, 출력에 나온 `파일:줄`로 바로 이동, 출력 묻기. Verilator·Icarus Verilog·Yosys 같은 도구가 설치돼 있으면 그대로 씁니다(앱에 넣지 않음).
  API 키·토큰 같은 이름의 환경 변수는 넘기지 않고, 출력에 보이는 비밀은 가립니다. 기본 10분 제한, 화면 출력 2MB 제한.
- **안드로이드**: 열기·강조·찾기·묻기·간단한 편집·저장. 명령 실행·Git·덩어리 적용은 없습니다(에이전트 수정은 예전 승인 창).

## 에이전트
- `write`/`edit`에 `reason`(바꾸는 이유)을 붙일 수 있고, 검토 화면에 보입니다.
- 승인 창에서 '허용'을 누르는 사이 파일이 바뀌었으면 덮어쓰지 않고 다시 읽으라고 알립니다. 파일 저장은 임시 파일에 쓴 뒤 바꿉니다.
- 수정 승인과 명령 실행 승인은 따로입니다. '파일 수정 자동 허용'이면 Code 화면에서도 바로 적용하고 '자동 적용' 기록만 남깁니다.

## 크기·성능(Chromium에서 측정)
- 편집기 묶음 `web/vendor/codemirror/codemirror.min.js` 748KB(gzip 251KB). 화면 파일 전체는 약 0.8MB 늘었습니다(설치 파일·APK는 압축되어 약 0.3MB).
- 코드 화면 열기 약 150ms, 950KB 파일 열기 약 130ms, 3MB 파일(읽기 전용) 약 220ms. 950KB 파일을 열었을 때 화면 JS 메모리 약 +2MB.
- 실제 Windows·macOS·안드로이드 기기에서의 측정은 아직 하지 않았습니다.

## 알려진 한계
- 진짜 대화형 터미널(PTY·ConPTY, SSH 대화형)은 없습니다. 실행 패널은 입력을 받지 않는 명령용입니다.
- SystemVerilog·Verilog·Tcl·Shell은 줄 단위 강조뿐이라 접기·구조 인식이 없고, '현재 블록'은 module/always/function 같은 줄 모양으로 짐작합니다.
- 대기 중인 변경 제안은 앱을 끄면 사라집니다(파일에는 아무것도 적용되지 않음).
- Code 화면·편집기는 Chromium 화면 시험과 CI 빌드에서 확인했습니다. 실제 WebView2·WKWebView·안드로이드 WebView에서 손으로 확인하는 일은 남아 있습니다.
