# POSCHAT 1.16.0 — Code 에이전트, POSCHAT Lab, AI 브라우저 에이전트, 사이드바 정리

## Code 에이전트: Codex·Claude Code처럼 작업을 맡기기 (새 기능)
**코드**를 열면 맨 앞에 **작업** 탭이 있습니다. 할 일을 적어 맡기면(Ctrl+Enter) 에이전트가 작업 폴더에서 스스로 계획을 세우고, 관련 코드를 찾아 읽고,
고치고, 테스트·빌드를 실행해 확인한 뒤 결과를 정리합니다. 파일 트리·편집기·Git·실행 패널은 그대로 옆에 있습니다.

- **진행 기록**: 계획 체크리스트, 읽은 파일, 바꾼 내용(diff), 실행한 명령과 출력(실시간), 최종 정리가 한 화면에 쌓입니다.
- **이어서 지시**: 작업은 세션입니다. 끝난 뒤 같은 작업에 이어서 지시하면 앞의 대화를 기억합니다. 지난 작업은 위의 목록에서 다시 엽니다.
- **승인(기본: 수정 자동 · 명령은 묻기)**: `.git` 폴더 안은 고치지 않고, 다음 커밋·편집기 열기 때 저절로 실행되는 설정(`.husky/`·`.pre-commit-config.yaml`·`.vscode/tasks.json`·`.envrc` 등)은 수정 자동이어도 묻습니다. 그 밖의 파일 수정은 바로 적용하되, 처음 고치기 전에 원래 내용을 보관합니다. **바뀐 파일**에서 파일마다 차이를 보고
  **되돌리기**, 또는 **이 작업의 변경 모두 되돌리기**로 작업 전으로 돌립니다(새로 만든 파일은 지움). 에이전트가 쓴 뒤 다른 변경이 생긴 파일은 덮어쓰지 않고 건너뜁니다.
  위쪽 메뉴에서 **수정·명령 모두 묻기**로 바꿀 수 있습니다. 명령 실행은 어느 쪽이든 매번 묻고, '이번 실행 동안 허용'이 없습니다.
- 명령은 실행 패널과 같은 실행기로 돕니다: 출력 실시간 표시, 비밀 환경 변수를 넘기지 않음, 출력의 비밀 가리기, **멈춤**을 누르면 프로세스 트리까지 끝냄.
- 읽은 뒤 다른 프로그램이 파일을 바꿨으면 덮어쓰지 않습니다. git commit·push, 패키지 설치는 요청했을 때만 합니다(명령이므로 어차피 승인 창이 뜹니다).
- PC 전용입니다(안드로이드는 쓸 수 없음).

## POSCHAT Lab: 실험 기록·재현성·비교·AI 분석 (새 기능)
왼쪽 사이드바의 **Lab**. 자세히: [Lab 사용법](../lab-guide.md) · [구조](../architecture/poschat-lab.md)

- **실험(Experiment)과 Run**: 실험마다 실행 설정(명령·Python 스크립트·Jupyter 노트북), 파라미터, 결과 파일 패턴, 지표 규칙을 두고, 실행할 때마다 Run이 쌓입니다(#1, #2…).
  기록은 데이터 폴더의 `lab/lab.db`(SQLite, 형식 버전 관리). 기록을 지워도 작업 폴더의 코드·결과 파일은 지우지 않습니다.
- **실행**: Code 실행 패널과 같은 승인 창(명령·파라미터·위험 동작·네트워크)을 거칩니다. 파라미터는 Python이면 `--이름 값`, 명령이면 `{이름}` 자리, 모두 환경 변수 `POSCHAT_PARAM_<이름>`.
  상태: 대기·실행 중·완료·실패·취소됨·중단됨(앱 종료). 실패·취소한 Run도 남습니다. 앱이 실행 중에 꺼지면 다음에 열 때 '중단됨'으로 표시합니다.
- **재현성 기록**: 실행 직전의 Git 커밋·가지·원격(계정·토큰 뺌)·바뀐 파일, 커밋하지 않은 변경의 패치 사본과 해시, OS·Python·패키지 목록(pip freeze)·GPU·CUDA(nvidia-smi가 있으면),
  비밀이 아닌 환경 변수. 없는 도구는 설치하지 않습니다(Jupyter가 없으면 알려 드림).
- **결과 가져오기**: 밖(서버·다른 PC)에서 만든 CSV·TSV·JSON·JSONL·TXT·로그·PNG·SVG를 Run으로 남깁니다. 파일은 옮기지 않고 경로·크기·해시로 가리키며, 원본이 바뀌거나 없어지면 알립니다.
  Code 실행 패널의 기록도 가져올 수 있습니다.
- **지표**: 결과 파일에서 사용자가 고른 열·값만 지표가 됩니다(마지막·첫·최대·최소·평균). 머리글의 단위(`latency (ms)`, `power[mW]`)를 읽고, 빈 칸·NaN·±Inf·글자 칸은 빼고 계산하며 경고합니다.
  지표마다 출처(파일·열·행·해시)를 남깁니다. 같은 규칙을 다음 Run에도 자동으로 씁니다.
- **그래프**: 선·점·막대, 여러 Run 겹치기, 축 이름과 단위. 점이 많으면 고르게 뽑은 표본만 그리고 그렇다고 알리며, 통계(최소·최대·평균·표준편차)는 전체 데이터로 계산합니다. 그림 결과 미리 보기.
- **비교**: 고른 Run의 파라미터·코드 버전·환경·상태·시간·지표·결과 파일을 나란히, 다른 조건은 강조합니다. 단위가 다른 지표, 다른 커밋, 커밋하지 않은 변경, 다른 환경은 경고합니다.
- **AI 분석**: 고른 Run 기록만 채팅에 첨부합니다(외부 데이터로 감쌈, 지금 고른 채팅 모델로 보냄). 기록에 없는 값을 지어내지 않고, 관찰과 해석을 나누고,
  상관관계를 인과로 단정하지 않고, Run ID를 근거로 달라고 요청합니다. AI는 실험을 실행하지 않습니다. 고른 요약은 **프로젝트 기억에 남기기**로 저장합니다.

## AI 브라우저 에이전트 (새 기능)
에이전트가 옆 **브라우저**의 페이지를 직접 조작합니다: 살펴보기(스냅샷)·누르기·입력·고르기·스크롤·기다리기·글 읽기·화면 캡처·주소 열기·뒤로·앞으로·새로 고침.
자세히: [보안](../browser-agent-security.md) · [구조](../architecture/browser-agent.md)

- 스냅샷은 조작할 수 있는 요소를 e1, e2…로 보여 주고, 이 ID는 그 스냅샷에서만 유효합니다(이동·새로 고침·사용자의 직접 조작 때 무효). 동작 전에 요소가 그대로인지 다시 확인하고, 동작 뒤 주소·제목으로 결과를 확인합니다.
- **승인**: 읽기·스크롤·기다리기와 같은 사이트 안 링크 이동은 바로 합니다. 사이트(호스트)마다 처음 누르기·입력·고르기를 할 때, 에이전트가 주소를 만들어 열 때(처음 한 번),
  처음 가는 사이트와 로컬/사설 네트워크(localhost·192.168.x 등, 매번)로 갈 때는 승인을 받습니다. 이 사이트 승인은 '모두 자동' 설정이나 '이번 실행 동안 허용'으로 건너뛰지 않습니다.
  제출·삭제·전송·업로드·구매·계정 변경·로그인·비밀번호·OTP·다운로드·GitHub 병합·리뷰 제출·권한 허용, 그리고 확인·동의·저장 버튼은 설정과 관계없이 언제나 묻습니다. 이름이 없거나 같은 이름이 여럿인 요소는 한 번 더 확인합니다.
  파일 올리기는 하지 않습니다(사용자가 직접).
- 비밀번호·인증 코드 칸에 넣은 값은 기록·화면·AI 관찰에 남기지 않습니다. 내려받은 파일은 실행하지 않습니다.
- 제한: 한 번에 브라우저 동작 40번·10분, 같은 동작 세 번 반복 금지. 브라우저 막대에 진행 상황(동작·상태·횟수·시간)과 **일시정지·계속·멈춤**이 보입니다. 단계마다 채팅에도 남습니다.
- 웹페이지 글은 외부 데이터로 감싸 AI에게 주므로 페이지 속 "이전 지시를 무시하라"는 지시로 읽히지 않습니다. 웹페이지에는 여전히 앱 API가 없습니다.

- 기능 버튼(PO노트·브라우저·논문·코드·Lab·라이브러리·자동화·플러그인)을 두 줄 격자로 묶고 아래 메뉴(작업 폴더~설정)를 약 25% 줄여, 채팅 목록이 남는 높이를 모두 씁니다.

## 고친 문제
- Code 화면: 창이 낮으면 편집기 자리의 안내 글이 아래 '실행' 패널 위로 넘쳐 겹쳐 보이던 문제(1.15).

## 안드로이드
- 이번 버전부터 안드로이드 앱은 따로 요청하지 않으면 기능을 맞추지 않습니다(공유 Python·화면 코드는 그대로 들어감). Lab은 기록 보기·가져오기·그래프만 되고 실행은 막혀 있으며,
  Code 에이전트와 브라우저 에이전트는 PC 전용입니다.

## 알려진 한계
- 브라우저 에이전트의 네이티브 동작(WebView2·WKWebView에서 스냅샷·입력·제출·캡처)은 CI의 실제 창 시험(browser-spike)으로 확인합니다. 로컬 시험은 Chromium으로 했습니다.
- iframe 안의 요소, 그림자 DOM(shadow DOM), 캔버스로 그린 화면은 스냅샷에 나오지 않습니다. 사람처럼 마우스를 움직이는 동작(드래그·호버)은 없습니다.
- Lab의 Jupyter 실행은 `nbconvert`로 노트북 전체를 실행하며 셀 단위 파라미터 주입(papermill)은 하지 않습니다(파라미터는 환경 변수).
- Code 에이전트의 되돌리기는 이 작업이 바꾼 파일만 다룹니다. 에이전트가 실행한 명령이 만든 파일(빌드 결과 등)은 되돌리지 않습니다.
- 모든 새 화면은 Chromium 화면 시험과 CI로 확인했습니다. 실제 WebView2·WKWebView 앱에서 손으로 확인하는 일은 남아 있습니다.
