# POSCHAT Code 사용법 (1.15)

작업 폴더의 코드를 전체 화면으로 열고, 고치고, AI에게 묻고, 에이전트가 고친 내용을 검토하고, 명령을 실행합니다.

## 열기
1. 왼쪽 아래 **작업 폴더**에서 프로젝트 폴더를 고릅니다(Code 화면은 이 폴더 안의 파일만 열고 저장합니다).
2. 왼쪽 위 **코드**를 누르면 채팅 자리 전체에 코드 화면이 열립니다(1.17.2부터 하나의 화면 — 채팅과 나누어 띄우지 않습니다).
   - 왼쪽 패널은 **파일 · Git · 변경 검토** 탭, 아래 패널은 **터미널**입니다(1.18). 아래 패널 위쪽 막대를 끌어 높이를 바꿉니다(다음에도 기억).
     왼쪽 위 아이콘은 왼쪽 패널을 숨기거나 보입니다.
   - 사이드바의 대화·**새 채팅**·PO노트·Lab·라이브러리·**논문**·**브라우저**를 누르거나 오른쪽 위 ×를 누르면 코드 화면은 닫힙니다.
     다시 **코드**를 누르면 열린 탭과 저장하지 않은 내용이 그대로 있습니다. **AI에게 묻기**도 채팅으로 돌아가 묻습니다.

## 파일
- 폴더를 눌러 펼치고, 파일을 눌러 탭으로 엽니다. 위쪽에 **최근 파일**이 있습니다.
- 찾기 칸: **이름**(경로에 든 글자) 또는 **내용**(파일 안의 글자)을 고르고 Enter. 결과를 누르면 그 줄로 갑니다. Esc 또는 **트리로**.
- 도구: **새 파일**·**새 폴더**(작업 폴더 기준 경로, 예: `rtl/top.sv`), **숨김 파일 보이기**, **새로 고침**, **설정**(제외할 폴더, 에이전트 수정 검토 방식, 실행 제한 시간).
- 파일에 마우스를 올리면 **이름 바꾸기**·**지우기**. 지운 파일은 데이터 폴더의 `code-trash`로 옮겨지므로 되살릴 수 있습니다.
- Git 저장소면 이름 옆에 `M`(수정)·`?`(새 파일)·`U`(충돌)가 붙습니다.
- 1MB가 넘는 파일은 읽기 전용, 8MB가 넘는 파일과 그림·실행 파일 같은 바이너리는 열지 않습니다.

## 편집·저장
- **저장**: Ctrl+S(맥 ⌘+S) 또는 저장 아이콘. 저장하지 않은 탭에는 ●가 붙습니다.
- **되돌리기·다시 하기**(Ctrl+Z·Ctrl+Y), **찾기·바꾸기**(Ctrl+F, 줄로 이동 Ctrl+Alt+G), **긴 줄 접어 보기**.
- 원래 인코딩(UTF-8·BOM·CP949)과 줄 끝(LF·CRLF), 마지막 줄 바꿈을 그대로 둡니다. 아래 상태 줄에 줄·칸·언어·인코딩·줄 끝이 보입니다.
- 다른 프로그램이나 에이전트가 파일을 바꿨으면 알려 줍니다. 저장할 때 바뀐 것을 발견하면 **내 내용으로 덮어쓰기**·**디스크 내용으로 다시 열기** 중에서 고릅니다.
- 앱이 갑자기 닫혀도 저장하지 않은 내용은 이 기기에 잠깐 보관되어, 다음에 그 파일을 열면 **되살리기**를 물어봅니다(파일에 자동 저장하지 않습니다).

## AI에게 묻기
1. 코드를 선택하고(선택하지 않으면 커서가 있는 함수·블록) 편집기 위 **AI에게 묻기 ▾**를 누릅니다.
2. **범위**: 선택한 부분 / 현재 함수·블록 / 파일 전체 / 관련 파일 함께(열린 파일·최근 파일에서 고르기).
3. **하고 싶은 일**: 코드 설명 · 오류 분석 · 성능 개선 · 리팩터링 제안 · 주석 생성 · 테스트 코드 제안 · RTL 로직 검토.
4. 채팅 입력창에 파일 경로·언어·줄 범위가 붙은 첨부와 질문이 들어갑니다. 질문을 고쳐 보내세요.

보낸 코드는 지금 고른 AI 모델 API로 전송됩니다. 작업 폴더 전체를 보내지 않습니다.

## 에이전트가 고친 내용 검토
에이전트 모드에서 Code 화면을 열어 두면, 에이전트의 파일 수정이 승인 창 대신 왼쪽 패널의 **변경 검토**와 편집기의 검토 탭에 뜹니다.
- 덩어리마다 체크를 켜고 끄거나 **이것만**을 누른 뒤 **고른 변경 적용**. **모두 적용**·**모두 거부**도 있습니다.
- **고쳐서 적용**: 제안 내용을 직접 고친 뒤 적용합니다.
- 받아들이기 전에는 파일이 바뀌지 않습니다. 검토하는 사이 파일이 바뀌었으면 충돌로 알리고, **현재 파일에 맞춰 적용**은 덩어리 앞뒤가 그대로일 때만 됩니다.
- Python·JSON은 일부만 적용했을 때 문법이 깨지면 미리 알려 줍니다.
- 에이전트는 어느 덩어리가 적용됐는지 알고 다음 단계를 정합니다. Code 화면을 닫으면 대기 중인 제안은 예전 승인 창으로 넘어갑니다.
- 승인이 필요한지는 **설정 → 에이전트 권한**이 정합니다. '파일 수정 자동 허용'이면 바로 적용하고 목록에 '자동 적용'으로 남깁니다.
  Code 설정에서 '항상 예전 승인 창으로'를 고를 수도 있습니다.

## Git
왼쪽 패널의 **Git** 탭(작업 폴더가 Git 저장소일 때, 1.18부터 아래 패널에서 옮김):
- 가지, 원격보다 앞섬·뒤처짐, 충돌·스테이지됨·바뀜·새 파일 목록. 파일을 누르면 차이(diff) 탭이 열립니다.
- 체크한 파일만 **스테이지**·**스테이지 취소**. 아무것도 자동으로 스테이지하지 않습니다.
- **AI: 변경 설명 / 코드 리뷰 / 커밋 메시지 제안**: 차이를 첨부하고 질문을 넣습니다(커밋 메시지는 스테이지한 변경으로).
- 메시지를 쓰고 **스테이지한 변경 커밋** → 확인 창에서 커밋. 푸시는 하지 않습니다(GitHub 커넥터나 다른 도구로).

## 터미널 (1.18)
아래 패널은 진짜 터미널입니다(1.17까지의 '실행' 패널을 바꿈). 코드 화면을 열면 작업 폴더에서 셸이 열립니다.
- 셸: Windows는 **PowerShell**(없으면 cmd, ConPTY), macOS·Linux는 로그인 셸(`$SHELL`, 보통 zsh·bash). vim·ssh·python 대화형처럼 입력을 받는 프로그램도 그대로 씁니다.
- **+** 로 터미널을 더 엽니다(6개까지). 탭을 눌러 오가고, 탭의 ×로 닫습니다(셸과 그 셸이 띄운 프로그램까지 끝냅니다). `exit`로 끝난 터미널은 아무 키나 누르면 닫힙니다.
- **복사**: 글을 고르고 Ctrl+C(또는 Ctrl+Shift+C). 고른 글이 없으면 Ctrl+C는 셸에 보냅니다(실행 중인 명령 멈춤). **붙여 넣기**: Ctrl+V. 맥은 ⌘C·⌘V.
- **Ctrl+`**: 아래 패널 열기·접기. 패널 제목 **터미널**을 눌러도 됩니다.
- **AI에게 묻기**: 고른 글(없으면 끝부분 200줄)을 채팅에 첨부하고 채팅으로 갑니다. 색·커서 같은 제어 글자는 빼고, 앱이 아는 비밀(키·토큰)은 가립니다.
- 직접 치는 셸이라 **승인 창이 없습니다.** 작업 폴더는 시작 위치일 뿐 격리가 아니고, 명령은 내 계정 권한으로 실행됩니다.
- 이름에 key·token·secret 같은 말이 든 환경 변수(예: `OPENAI_API_KEY`)는 터미널에 넘기지 않습니다. SSH 에이전트(`SSH_AUTH_SOCK`)는 넘깁니다.
- 코드 화면을 닫거나 다른 화면으로 가도 터미널은 그대로 돌고, 앱을 끄면 모두 끝납니다.
- 에이전트의 명령 실행(승인 창·'다시 묻지 않기')과 작업 탭의 `!명령`은 그대로이고, 이 터미널과 따로입니다.
- Verilator·Icarus Verilog·Yosys·ngspice 같은 도구는 POSCHAT에 들어 있지 않습니다. 설치돼 있으면 터미널에서 바로 씁니다.

- Verilog·SystemVerilog·Tcl·Shell은 키워드·주석·문자열·숫자 강조뿐이고 접기는 없습니다. SPICE는 간단한 강조만.
- 대기 중인 변경 제안은 앱을 끄면 사라집니다(파일에는 적용되지 않습니다).

## Code 에이전트: 작업 맡기기 (1.16)
> 1.17.2부터 작업 탭은 터미널 화면입니다. 위쪽 메뉴·단추 대신 키와 명령으로 씁니다 — [터미널처럼 쓰기](#code-에이전트-3-터미널처럼-쓰기-1172).

코드 화면 맨 앞의 **작업** 탭에서 할 일을 적고 **맡기기**(Ctrl+Enter)를 누르면, 에이전트가 Codex·Claude Code처럼 작업 폴더에서 스스로 일합니다.

- 계획(체크리스트) → 관련 파일 찾기·읽기 → 고치기 → 테스트·빌드 실행 → 실패하면 다시 고치기 → 정리. 단계마다 진행 기록에 쌓이고, 고친 곳은 diff로, 명령 출력은 실시간으로 보입니다.
- 끝난 뒤 같은 작업에 **이어서 지시**할 수 있습니다. 지난 작업은 위쪽 목록에서 다시 엽니다.
- **승인 방식**(위쪽 메뉴): 기본은 **수정 자동 · 명령은 묻기**. 파일 수정은 바로 적용하고 원래 내용을 보관합니다. **수정·명령 모두 묻기**로 바꾸면 수정도 승인 창에서 묻습니다. `.git` 폴더 안은 고치지 않고, 커밋 훅·편집기 작업 설정처럼 저절로 실행되는 파일(`.husky/`·`.pre-commit-config.yaml`·`.vscode/tasks.json`·`.envrc` 등)은 수정 자동이어도 묻습니다.
- **바뀐 파일**: 파일마다 **차이**(작업 전 → 지금)와 **되돌리기**, **이 작업의 변경 모두 되돌리기**. 새로 만든 파일은 지웁니다. 에이전트가 쓴 뒤 사용자나 다른 프로그램이 고친 파일은 덮어쓰지 않고 건너뜁니다.
- **멈춤**: 진행 중인 단계와 실행 중인 명령을 멈춥니다(프로세스 트리까지).
- 저장하지 않은 편집기 탭이 있으면 알립니다. 에이전트는 디스크의 내용을 봅니다.
- 커밋은 하지 않습니다(요청하면 명령이므로 승인 창이 뜹니다). 끝난 뒤 **Git에서 보기·커밋**으로 직접 커밋하세요.

## Code 에이전트 2: Claude Code·Codex처럼 (1.17.1)
- **권한 모드**(작업 탭 위쪽 메뉴, `/mode`로도 바꿈)

  | 모드 | 파일 수정 | 명령 실행 |
  |---|---|---|
  | 계획 모드 | 하지 않음(읽기·찾기만) | 하지 않음 |
  | 매번 묻기 | 승인 창 | 승인 창 |
  | 수정 자동(기본) | 바로 적용(되돌리기 가능) | 승인 창 |
  | 전체 자동 | 바로 적용 | 바로 실행. 위험한 동작(삭제·초기화·강제 푸시 등)·인터넷을 쓰는 명령만 승인 창 |

  계획 모드의 답은 **제안한 계획**으로 표시되고, **이 계획으로 진행**을 누르면 같은 작업에서 고치기 시작합니다(계획 모드를 벗어나 수정 자동으로).
- **다시 묻지 않기**: 명령 승인 창의 **허용 · '명령' 다시 묻지 않기**를 누르면 이 작업 폴더에서 같은 명령(앞 낱말: 예 `npm test`, `python -m pytest`, `python test_calc.py`)은
  묻지 않습니다. `&&`·`|`·`;`·`>`로 이은 명령, 위험한 동작, 인터넷을 쓰는 명령은 규칙이 있어도 묻고, `python`처럼 무엇이든 실행할 수 있는 넓은 규칙은 만들지 않습니다.
  규칙은 작업 탭 안내의 **다시 묻지 않는 명령**에서 지웁니다.
- **추가 지시**: 에이전트가 일하는 동안 아래 칸에 쓰고 **추가 지시**(Ctrl+Enter)를 누르면 다음 단계부터 반영합니다.
- **슬래시 명령**(입력 칸에 `/`를 치면 목록이 뜹니다)

  | 명령 | 하는 일 |
  |---|---|
  | `/init` | 작업 폴더를 살펴보고 AGENTS.md(프로젝트 지침)를 만든다 |
  | `/review [초점]` | 커밋하지 않은 Git 변경을 코드 리뷰한다(계획 모드, 고치지 않음) |
  | `/test [대상]` | 테스트를 찾아 실행하고 실패하면 고친다(테스트를 지우거나 건너뛰게 바꾸지 않음) |
  | `/plan 할 일` | 이 지시만 계획 모드로 |
  | `/undo` | 마지막 지시로 바뀐 파일만 그 지시 전으로(그 뒤 사람이 고친 파일은 건너뜀) |
  | `/compact` | 이 작업의 지난 대화를 요약 하나로 줄인다(긴 작업) |
  | `/new` · `/mode 모드` · `/help` | 새 작업 · 권한 모드 바꾸기 · 목록 |
- **프로젝트 지침과 정보**: 작업 폴더 맨 위의 **AGENTS.md**·**CLAUDE.md**(`.claude/CLAUDE.md`)를 읽고 따릅니다(앱의 승인·안전 규칙이 먼저).
  package.json·pyproject.toml·Makefile·Cargo.toml·go.mod 등으로 테스트·빌드·린트 명령을 짐작하고, Git 브랜치·바뀐 파일도 에이전트에게 알려 줍니다.
- **격리 작업 공간(git worktree)**: 새 작업을 맡길 때 **격리 작업 공간(git worktree)에서**를 켜면, 데이터 폴더에 따로 만든 작업 공간(브랜치 `poschat/<작업>`)에서
  고치고 명령을 실행합니다. 원래 작업 폴더는 그대로이고, 끝난 뒤 **전체 차이**를 보고 **원래 폴더에 적용**(먼저 검사, 겹치면 3-way, 그래도 겹치면 아무것도 바꾸지 않음),
  **브랜치로 남기기**(그 브랜치에 커밋해 두고 Git으로 직접 합치기 — 커밋 훅은 돌리지 않음) 또는 **버리기**를 고릅니다. Git 저장소(커밋 1개 이상)에서만 되고, 설치하지 않은 의존성(node_modules·가상환경)은 격리 공간에 없을 수 있습니다.
- **에이전트의 새 도구**: 줄 번호를 붙여 읽기(긴 파일은 나눠서), 이름으로 파일 찾기(glob), 같은 글 모두 바꾸기, 한 파일 여러 곳 한 번에 고치기(하나라도 안 맞으면 아무것도 안 바꿈),
  개발 서버 같은 끝나지 않는 명령을 백그라운드로 돌리고 출력 보기·멈추기(작업이 끝나면 멈춤), 무엇을 왜 하는지 한 줄 설명(💬).

## Code 에이전트 3: 터미널처럼 쓰기 (1.17.2)
작업 탭 전체가 Claude Code 같은 터미널입니다. 마우스 없이 키보드만으로 맡기고, 승인하고, 되돌릴 수 있습니다.

- **입력**: 맨 아래 `>` 줄에 쓰고 **Enter**. 줄 바꿈은 **Shift+Enter**(또는 줄 끝 `\` 다음 Enter). 일하는 중에 Enter를 누르면 **추가 지시**로 다음 단계부터 반영합니다.
- **기록**: Claude Code처럼 단계가 한 줄씩 쌓입니다.

  ```
  > test_calc.py가 통과하도록 calc.py를 고쳐 줘
  ● Read(calc.py)
    ⎿ 2줄 읽음 (ctrl+o로 펼치기)
  ● Update(calc.py)
    ⎿ 1줄 더함, 1줄 지움
       2 -     return a - b
       2 +     return a + b
  ● Bash(python test_calc.py)
    ⎿ 종료 코드 0, 0.1초
       통과
  ● calc.py의 add를 고쳤고 test_calc.py가 통과했습니다.
  ✻ 12초 동안 일했습니다 · 파일 1개 바꿈 (/diff 차이 · /undo 되돌리기)
  ```
  접힌 출력은 **Ctrl+O**로 모두 펼치고(다시 누르면 접힘), 한 단계만 보려면 그 줄을 누릅니다. 진행 줄(`✻ 생각하는 중… (8초 · esc로 멈춤)`)이 입력 줄 바로 위에 보입니다.
- **승인**: 대화 상자 대신 기록 안에서 묻습니다. ↑↓와 Enter, 또는 숫자로 고릅니다.

  | 고르기 | 명령 실행 | 파일 수정(매번 묻기 모드) |
  |---|---|---|
  | 1 | 예 | 예 |
  | 2 | 예, 이 작업 폴더에서 이 명령은 다시 묻지 않기 | 예, 이 작업 동안 수정은 묻지 않기(수정 자동으로 바뀜) |
  | 3 · Esc | 아니요, 다르게 하라고 알려 주기 → 쓰고 Enter(비우면 그냥 거부) | 같음 |

  작업 탭이 보이지 않을 때(채팅 화면 등) 온 승인은 예전처럼 창으로 묻습니다.
- **권한 모드**: **Shift+Tab**(또는 아래 상태 줄의 모드를 누름)으로 매번 묻기 → 수정 자동 → 계획 모드 → 전체 자동 차례로 바꿉니다. 작업 중에 바꿔도 다음 단계부터 따릅니다.
  계획 모드가 끝나면 '이 계획으로 진행할까요?'에서 1(수정 자동으로 진행)·2(수정할 때마다 묻기)·3(계획 더 다듬기)을 고릅니다.
- **입력 앞글자**

  | 앞글자 | 하는 일 |
  |---|---|
  | `/` | 명령(목록이 뜨고 ↑↓·Tab·Enter로 고름) |
  | `!` | 작업 폴더에서 명령을 바로 실행합니다(직접 친 명령이라 묻지 않지만, 위험한 동작·인터넷을 쓰는 명령은 한 번 더 묻습니다). 출력은 다음 지시의 맥락으로 에이전트에게 넘어갑니다. |
  | `#` | 프로젝트 지침 파일(AGENTS.md, 없으면 CLAUDE.md, 둘 다 없으면 AGENTS.md를 만듦) 끝에 `- 메모` 한 줄을 더합니다. 에이전트는 다음 지시부터 따릅니다. |
  | `@` | 파일·폴더 이름 자동 완성(Tab). 보내면 그 파일 내용(폴더는 목록)을 지시에 붙입니다. 작업 폴더 밖·링크·바이너리는 붙이지 않고, 파일 10개·20만 자까지입니다. |
- **단축키**: Esc 멈춤(자동 완성이 열려 있으면 닫기) · 쉬고 있을 때 Esc 두 번 마지막 지시 되돌리기 · ↑↓ 지난 입력(이 컴퓨터에 200개) · Tab 자동 완성 ·
  Ctrl+O 출력 펼치기 · Ctrl+L 화면 비우기(기록은 그대로) · Ctrl+C 입력 지우기(비었으면 멈춤) · `?` 단축키 목록.
- **명령**: 위쪽 메뉴와 단추가 하던 일은 명령으로 합니다.

  | 명령 | 하는 일 |
  |---|---|
  | `/clear` (`/new`) | 화면을 비우고 새 작업 |
  | `/resume [번호]` | 지난 작업을 골라 이어서 |
  | `/status` | 작업 폴더·Git 브랜치·권한 모드·모델·프로젝트 지침·작업 정보 |
  | `/diff` | 이 작업이 바꾼 파일의 차이(격리 작업이면 전체 차이) |
  | `/revert [파일]` | 바꾼 파일(비우면 모두)을 작업 전으로 |
  | `/undo` (`/rewind`) | 마지막 지시로 바뀐 파일만 그 지시 전으로 |
  | `/todos` | 지금 계획 |
  | `/mode [모드]` · `/plan` | 권한 모드 고르기 · 계획 모드로 |
  | `/permissions` | 다시 묻지 않는 명령 보기·지우기 |
  | `/memory` | 프로젝트 지침 파일을 편집기에서 열기 |
  | `/worktree 할 일` | 격리 작업 공간(git worktree)에서 새 작업 |
  | `/apply` · `/keep` · `/discard` | 격리 작업을 원래 폴더에 적용 · 브랜치로 남기기 · 버리기 |
  | `/delete` | 이 작업 기록 지우기(파일은 그대로) |
  | `/init` `/review` `/test` `/plan 할 일` `/compact` `/help` | 1.17.1과 같음 |
- **프로젝트 명령**: 작업 폴더의 `.poschat/commands/이름.md`(또는 Claude Code와 같은 `.claude/commands/이름.md`)가 `/이름` 명령이 됩니다.
  본문의 `$ARGUMENTS`는 명령 뒤에 쓴 글로 바뀌고(없으면 끝에 붙음), 맨 위 `---` 머리말의 `description:`이 목록의 설명입니다. 내장 명령과 같은 이름은 쓰지 않습니다.
  저장소에 적힌 글이므로 앱의 승인·안전 규칙보다 앞서지 않습니다.
