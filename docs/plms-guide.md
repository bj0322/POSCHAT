# PLMS 로그인·수업·공지·자료 읽기 (베타, 1.18.6)

> **베타 기능**: 실제 학교 계정·Windows·macOS 앱에서의 손 확인이 끝나지 않았다. 사이드바에서는 기능 버튼 맨 아래에 **베타** 표식과 함께 두고, 창 제목·사용법 가이드·설정에도 베타로 표시한다. 동작이 달라지거나 실패할 수 있으니 중요한 공지·마감은 PLMS 사이트에서 직접 확인한다.

1. (선택) 설정의 **PLMS 계정**에 아이디·비밀번호를 저장한다. 저장하면 화면에 붙이지 않은 웹 뷰(백그라운드)에서 SSO 로그인을 한다. 사이드바 **PLMS → 로그인**이나 **내 수업 불러오기**, 채팅·Code 에이전트의 PLMS 조회가 세션이 없을 때 알아서 로그인한다. 브라우저는 열리지 않는다. 저장하지 않았으면 **SSO 로그인**을 눌러 오른쪽 내장 브라우저에서 직접 입력한다. StonePASS 같은 추가 인증이 필요하면 어느 쪽이든 브라우저가 보이고 사용자가 직접 마친다(마치면 다시 숨는다). 학교가 로그인을 거부하면 10분 동안은 자동으로 다시 시도하지 않는다(계정 잠김 방지). 기본 브라우저에서 로그인한 상태는 자동으로 공유되지 않는다.
2. **PLMS → 내 수업 불러오기**를 누른다. **이번 학기 수업**이 먼저 나오고 예정·지난 학기 수업은 따로 묶인다(Moodle의 수업 시작·종료일로 가른다. 종료일이 없는 수업은 시작 후 200일이 지나면 지난 학기로 본다. 날짜를 알 수 없으면 이번 학기 쪽에 둔다). 수업을 선택하면 종류 칩(공지·게시판·자료·과제·기타)과 주차·주제별 묶음으로 항목이 나온다.
3. 공지 게시판 → 게시글 → 첨부 파일 순서로 누르거나, 강의자료를 선택한다. PDF는 화면에서 쪽별로 보고, PPT·PPTX는 설치된 PowerPoint 호환 앱에서 열거나 파일로 받을 수 있다. 텍스트 추출은 PDF, docx, pptx, xlsx, xlsm, hwp, hwpx, txt, md, csv를 20MB까지 지원한다. 긴 글은 **이어서 읽기**를 누른다. 예전 PPT와 스캔 PDF는 텍스트를 추출할 수 없다.
4. **에이전트에게 수업 정리 맡기기** 또는 **이 자료 묻기**를 누른다. 질문을 확인하고 보내면 에이전트가 자료를 조회한다. 수업 전체를 요청하면 목록과 자료를 이어 읽도록 안내하며, 답변에 실제로 연 수업·자료 수가 표시된다. 단계 한도, 접근 오류, 이미지나 읽지 못하는 형식 때문에 모든 쪽을 확인했다고 보장하지는 않는다. 채팅에서는 에이전트 모드만 켜면 되고 브라우저를 열어 둘 필요가 없다. 채팅에 PLMS 수업·공지·자료를 직접 물어봐도 된다. Code 작업 에이전트도 로그인 후 같은 조회 도구로 자료를 읽을 수 있다(브라우저 조작 권한은 주지 않는다). PLMS만 조회할 때는 작업 폴더가 없어도 된다.
5. 로그인 만료·권한 오류가 나면 다시 로그인한다. **연결 해제**는 조회 기능을 끄고 PLMS 도메인 전용 쿠키를 지운다. POSTECH 공통 SSO 세션까지 로그아웃하는 기능은 아니며 기존 대화 기록도 지우지 않는다.

## 에이전트 도구

- `plms_courses`: 현재 계정의 참여 수업 목록. 각 수업에 `status`(current·future·past·unknown)·`term`이 있고 이번 학기가 앞이다. 에이전트는 사용자가 따로 말하지 않으면 이번 학기 수업만 다룬다.
- `plms_course(course_id)`: 참여 수업 본문과 지원하는 공지·자료 링크(항목마다 `kind`·`section`).
- `plms_read(course_id, url, parent=[], query="", offset=0)`: 발견한 링크의 본문·파일 읽기. 게시판·폴더·게시글을 거쳤다면 `parent`에 수업에서부터 거친 상위 링크를 순서대로 지정한다(최대 4단계). 반환된 `next_offset`으로 이어 읽는다.

에이전트 목록은 12개씩 반환하며 `next_item_offset`을 같은 도구의 `item_offset`에 넣어 나머지 목록을 확인한다. 수업·게시판의 링크는 최대 400개까지 수집하고, 더 있으면 `items_truncated`로 알린다.

수업별로 학교가 허용한 읽기 권한을 그대로 사용한다. 주소를 임의로 만들어 다른 수업 자료를 가져오는 방식은 지원하지 않는다. 수업 목록은 내 강좌 페이지와, 지원하는 경우 Moodle의 수강 목록 조회 AJAX 함수로 확인한다. 별도 Moodle API 토큰을 요구하지 않는다.

## 데이터와 한계

- OTP·StonePASS 코드는 POSTECH 웹페이지에 직접 입력하며 앱은 저장하지 않는다. 설정에 저장한 아이디·비밀번호는 OS 보안 저장소(없으면 소유자만 읽는 앱 전용 파일)에 있고 config.json·동기화·로그·화면 상태·모델로 나가지 않는다. 자동 입력은 `https://*.postech.ac.kr` 주소의 로그인 창에서만, 로그인 한 번당 한 번 보낸다(틀린 비밀번호를 반복해 계정이 잠기는 일과 2단계 인증 칸에 넣는 일을 막는다). 설정에서 **저장된 계정 지우기**로 지운다. 브라우저 쿠키는 로컬 네이티브 저장소에 있고, 조회할 때만 메모리로 읽는다. 외부 호스트로 리다이렉트되면 인증 쿠키를 보내지 않고 중단한다.
- 에이전트가 읽은 공지·강의자료는 대화 기록에 일부 남고 사용자가 선택한 AI 서비스에 전송될 수 있다. 자료는 외부 데이터로 표시한다. 개발자 업데이트 서버로 전송하지 않는다.
- 텍스트 추출용 임시 파일은 읽은 뒤 지운다. PowerPoint 앱으로 연 원본은 임시 폴더에 두고 앱이 정상 종료될 때 정리하며, 사용자가 직접 받은 파일은 선택한 다운로드 위치에 남는다. 상시 동기화·일괄 다운로드는 하지 않는다.
- Windows WebView2·macOS WKWebView가 필요하다(숨은 웹 뷰도 같은 네이티브 뷰다). 네이티브 뷰가 아닌 대체 브라우저 모드는 PLMS 쿠키 조회를 지원하지 않는다.
- 자동 제출·출석·퀴즈 응시·성적 변경은 제공하지 않는다. 자료 조회 자체가 PLMS 서버의 ‘열람함’ 기록에 남을 수 있다.
- 학교 밖 사이트, 동영상, 특수 강의 모듈, 동적 전용 게시판은 읽지 못할 수 있다. 지원하지 않는 링크는 원문 브라우저에서 확인한다. 학교 화면·설정 변경에 따라 파서 보완이 필요할 수 있다.
- 공유 브라우저를 사용하는 에이전트는 한 번에 한 세션이다. 로그인·연결 해제는 브라우저를 쓰는 에이전트를 멈춘 뒤 한다. 연결을 해제해도 이미 질문에 포함된 자료와 대화는 남는다.

## 검증 범위

가짜 로그인 대시보드·수업·중첩 게시판·파일 응답을 이용해 수강 목록, 본문, 문서 추출, 만료, 외부 주소 차단, 크기 제한, 취소, 에이전트·화면 흐름을 시험한다. 네이티브 CI는 두 운영체제의 쿠키 API 호출을 점검한다. **실제 POSTECH 계정으로 SSO·StonePASS 왕복과 로그인 후 수업별 화면을 확인하는 손 시험은 아직 수행하지 않았다.** 특히 1.18.5의 자동 입력은 학교 로그인 화면의 입력 칸·버튼 구조를 일반적인 형태로 가정해 만들었으므로 실제 화면에서 채워지지 않으면 직접 입력하면 되고, 학기 구분과 주차별 묶음도 실제 수업 페이지 구조에 따라 보완이 필요할 수 있다. 학교 계정별 기능 호환을 확인한 것으로 해석하지 않는다.
