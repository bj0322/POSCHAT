# Adaptive AI 벤치마크 결과 (1.17, 2026-10-24)

**한 줄 요약**: 라우팅(모델을 부르지 않는 평가)은 측정했고, 실제 품질·비용 비교(로컬 모델·Cloud 모델을 부르는 실행)는 **아직 하지 않았다**.
개발 환경에 Ollama 실행 파일을 돌릴 수 없었고(외부 실행 파일 실행이 막힘) Cloud API 키도 없었다. 아래 비용 절감 값은 모두 '라우팅만 본 추정'이며
품질이 유지된다는 근거가 아니다.

## 1. 오프라인 라우팅 평가(`python tools/adaptive_benchmark.py --offline --policy <정책>`)
가정: 로컬 모델이 있다(문맥 32K, 이미지 없음), Cloud는 Claude Sonnet 5.5(크레딧 근거 있음). 로컬 답이 모두 받아들여질 만하다고 볼 때의 값이다(승격은 넣지 않음).

| 정책 | 구성 | 로컬 비율 | 라우팅 정확도 | 잘못 로컬로(cloud_needed→로컬) | 놓친 로컬(local_ok→Cloud) | test 로컬 비율 | test 정확도 | test 잘못 로컬 |

| Balanced | C | 50.4% | 92.0% | 1 | 17 | 47.3% | 90.2% | 1 |

- Quality는 측정 기록이 없으면 로컬을 쓰지 않도록 만들어 0%가 맞다. 측정 기록(검증 결과·👍👎)이 20개 이상 쌓인 (모델, 작업)부터 로컬을 쓴다.
- 의미 분류(D)는 규칙(C)보다 조금 낫다(+0.4~0.9%p). 큰 차이는 아니며, 개선의 대부분은 규칙에서 왔다.
- '잘못 로컬로'는 모두 test 세트 사례다. Balanced 1건(paper-15: "이 결과를 재현하려면 **무엇이** 더 필요한지 … 분석해 줘" — '무엇'이 짧은 값 찾기로 잡혀
  연구 추론을 '쉬움'으로 봄), Economy 3건(그 사례 + web-21·web-29의 비판적 분석 질문을 Economy가 로컬로 허용). test를 보고 규칙을 고치면 평가가 오염되므로
  고치지 않고 남겼다. 실제로는 이런 답이 검증(QualityGate)에서 걸러지지 않을 수 있다(형식은 맞을 수 있으므로) — 알려진 한계.
- Balanced·D 분야별: general 로컬 94%(정확도 94%), browser 86.7%(100%), lab 50%(73.5%), paper 27.3%(88.6%), code 27.3%(100%), agent 0%(100%).
  Lab·Paper의 '계산해 줘' 문제는 정답 표시가 local_ok인데 라우터가 Cloud로 보낸다(작은 로컬 모델의 산술 오류를 막으려고 일부러 두었다 — 놓친 로컬 16건 대부분).
- **라우터 조정 이력**: 처음 규칙(조정 전)은 Balanced 로컬 24%·정확도 63.8%였다. dev의 틀린 사례만 보고 일반 규칙(첨부 자료의 짧은 값 찾기·짧은 사실 질문·
  코드 설명은 쉬움, '제안·설계'는 연구, '검증 정확도'는 연구 낱말이 아님, 함수 이름 인식)을 더한 뒤 test 정확도 91.1%가 되었다. test도 같은 사람이 쓴 같은 꼴의
  데이터라 실제 사용자 요청에서는 더 낮을 수 있다.

- G의 18.3%는 처음부터 프런티어로 간 요청(주로 에이전트 단계 22개·코드 수정)의 입력 토큰 비율이다. 상담 73건에서 프런티어가 받는 질문·발췌 토큰은
  실제 실행에서만 알 수 있다(경량 모델이 질문을 만든다). 시험(`test_consult_sends_only_the_question_to_the_frontier`)에서는 긴 대화의 1/3 이하만 프런티어로 갔다.
- 경량 모델의 크레딧 단가는 앱에 근거가 없어(Claude Haiku·GPT-5 mini) 비용 절감률은 계산하지 않았다. 토큰 비율만 보인다.

## 2. 실제 실행(`--run`) — 미실행
| 구성 | 상태 |
|---|---|
| A cloud_only ~ G consult | **미실행** — 이 환경에 Ollama 실행 파일·Cloud 키가 없음 |

목표(API 비용 30% 이상 절감, 핵심 작업 성공률 하락 2%p 이내)의 **달성 여부는 확인하지 못했다**. 오프라인 값은 로컬·경량 답이 받아들여질 만하다는 가정 위의 상한이다.
사용자 PC에서 다음으로 측정한다(Cloud 비용 발생, 상한 필수):
```
python tools/local_ai_check.py --model qwen2.5:7b
python tools/adaptive_benchmark.py --run --configs A,B,E,F,G --local-model qwen2.5:7b --cloud-model claude-sonnet-5-5 \
    --light-model gpt-5-mini-gs-2025-08-07 --budget-calls 800 --repeats 2 --yes
```
결과를 받으면 이 문서의 2절에 표로 적고, 기준(성공률 하락 2%p 이내)을 넘는 작업 유형은 `LOCAL_ELIGIBLE`·`LIGHT_DIRECT`에서 빼거나 실험 기능으로 표시한다.

## 3. 자동 시험으로 확인한 것(가짜 모델)
- Local Only에서 Cloud 호출 0건(라우터·`api.cloud_guard`·PO노트·대화 요약·Code 에이전트), 승인 없는 도구 실행 0건, 부작용 한 번만, 상담 줄 화면 누출 0건.
- 전체 시험 결과는 PR 본문과 CI(license·tests·ui·windows·macos·android·browser-spike)를 본다.
