# 1.9 → 1.10 마이그레이션 가이드

## 자동으로 일어나는 일
- 처음 실행할 때 데이터 폴더의 `config.json`, `memory.md`, `USER.md`, `mcp.json`, `usage.json`, `threads/`(합계 300MB 이하일 때)를 `backups/<시각>-before-1.10/`에 한 번 복사한다. 설정의 `backup_1_10`에 경로가 남는다.
- 기존 파일의 형식은 바꾸지 않는다. 대화 메시지에는 선택 필드(`model`, `feedback`)만 더해질 수 있고 1.9는 이를 무시한다.
- 새 기능은 모두 꺼진 채로 시작한다. 기존 내장 MCP 서버·mcp.json 서버 구성은 그대로다.

## 바뀐 동작
- 에이전트의 MCP 도구 호출이 다시 동작한다(1.6~1.9.2의 NameError 수정).
- "이번 실행 동안 모두 허용"은 메시지 하나가 끝나면 사라진다(이전에는 앱을 끌 때까지 유지).
- 외부 서비스·웹·논문에서 온 도구 결과는 '외부 데이터' 표시로 감싸 모델에 전달된다(프롬프트가 조금 길어짐).
- 사이드바의 'MCP' 버튼은 '연결·도구'가 되었고 MCP 목록은 그 안의 탭이다.

## 되돌리기(1.9.2로)
1. 앱을 끈다. 2. GitHub Releases의 v1.9.2를 설치한다. 3. 필요하면 `backups/<…>-before-1.10/`의 파일을 데이터 폴더에 같은 이름으로 덮어쓴다(`threads/` 포함).
1.10이 만든 `memory/`, `research/`, `telemetry/`, `logs/`, `secrets.json`, `sync_state.json`, `device_id`는 1.9.2가 무시하므로 지우지 않아도 된다. 커넥터 토큰은 OS 보안 저장소의 `PostechChat` 항목에 남으니, 지우려면 1.10에서 '연결 해제'를 먼저 하거나 자격 증명 관리자·키체인에서 지운다.

## 기존 키를 보안 저장소로 옮기기(향후)
POSTECH API 키·Notion·Firecrawl 키는 하위 호환을 위해 1.10에서도 `config.json`에 있다. 다음 버전에서 백업 후 secret_store로 옮기는 이동을 계획한다(이번에는 하지 않음).
