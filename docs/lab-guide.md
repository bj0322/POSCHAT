# POSCHAT Lab 사용법 (1.16)

Lab은 실험의 조건·코드 버전·실행 환경·결과를 한곳에 기록하고, 여러 실행(Run)을 비교하고, AI에게 해석을 묻는 화면입니다.
왼쪽 사이드바의 **Lab**을 누르면 본문에 열립니다. 구조는 [architecture/poschat-lab.md](architecture/poschat-lab.md).

## 1. 실험 만들기
1. 작업 폴더를 고릅니다(실험 코드가 있는 폴더).
2. **+ 새 실험** → 이름과 설명(목표·가설)을 적습니다.
3. **실행 설정** 탭에서 실행 방식을 고릅니다.
   - **Python 스크립트**: 작업 폴더 안 `.py` 경로. 파라미터는 `--이름 값`으로 넘깁니다(`argparse`로 받으세요).
   - **명령**: 예) `vvp sim.out +BITS={bits}` — `{이름}` 자리에 파라미터 값이 따옴표로 감싸져 들어갑니다.
   - **Jupyter 노트북**: `.ipynb` 경로. `python -m nbconvert --execute`로 노트북 전체를 실행하고, 실행한 노트북 사본을 Lab 기록 폴더에 남깁니다.
     파라미터는 환경 변수로만 넘깁니다. 이 PC의 Python에 `nbconvert`가 없으면 알려 드립니다(POSCHAT은 설치하지 않습니다).
   - 어느 방식이든 파라미터는 환경 변수 `POSCHAT_PARAM_<이름>`, 전체는 `POSCHAT_PARAMS_JSON`, Run 번호는 `POSCHAT_RUN_ID`로도 넘깁니다.
4. **결과 파일**에 패턴을 적습니다(예: `out/*.csv, results/*.json`). 실행 중에 바뀐 작업 폴더 안의 파일만 Run에 붙습니다(옮기지 않음).
5. **설정 저장**.

## 2. 실행하기
**실행**(또는 **이 설정으로 실행**) → 파라미터 값을 고치고 **다음** → 승인 창에서 명령·작업 폴더·파라미터·위험할 수 있는 동작을 확인하고 **실행**.
- 실행 직전에 Git 커밋·가지·바뀐 파일(커밋하지 않은 변경은 패치 사본과 해시)과 OS·Python·패키지 목록·GPU·CUDA를 기록합니다.
- 상태: 대기 → 실행 중 → 완료/실패/취소됨. 앱이 실행 중에 꺼지면 다음에 Lab을 열 때 '중단됨(앱 종료)'으로 표시합니다. 실패·취소한 Run도 지우지 않습니다.
- **Run 상세**에서 출력을 실시간으로 보고 **멈춤**으로 멈춥니다. 개요의 **다시 실행**은 같은 설정·파라미터로 승인 창을 다시 엽니다(지금 코드로 실행합니다).

## 3. 밖에서 만든 결과 가져오기
**결과 가져오기** → 작업 폴더에서 찾은 결과 파일(CSV·TSV·JSON·JSONL·TXT·로그·PNG·SVG)을 고르거나 **다른 파일 고르기…**로 고릅니다.
Code 실행 패널에서 돌린 명령의 기록도 고를 수 있습니다. 조건(파라미터)·이름·메모를 적으면 '가져옴' 상태의 Run이 됩니다.
파일은 옮기거나 복사하지 않고 경로·크기·SHA-256으로 가리킵니다. 나중에 원본이 바뀌면 '바뀌었습니다', 없어지면 '없어졌습니다'로 알립니다.

## 4. 지표 뽑기
**Run 상세 → 결과 파일 → 미리 보기·지표 뽑기**에서 지표로 쓸 열(또는 JSON 값·로그의 `이름: 숫자`)을 고르고 방식(마지막·첫·최대·최소·평균), 이름, 단위를 정합니다.
- 단위는 머리글에서 읽습니다: `latency (ms)`, `power[mW]`, `delay_ns`. 직접 고칠 수 있습니다.
- 빈 칸·NaN·±Infinity·숫자가 아닌 글자는 빼고 계산하고 몇 개를 뺐는지 알려 드립니다. 숫자 값이 하나도 없으면 지표를 만들지 않습니다(추측하지 않음).
- 이름이 겹치는 열은 경고합니다. 지표마다 출처(파일·열·행·방식·파일 해시)가 남습니다.
- **다음 Run에도 같은 규칙으로 뽑기**를 켜 두면 실행이 끝날 때 같은 파일 이름에서 자동으로 뽑습니다(실행 설정 탭에서 규칙을 뺄 수 있음).
- 손으로 적은 지표는 출처가 '직접 입력'으로 남습니다.

## 5. 그래프
**그래프** 탭에서 결과 파일, X축 열(비우면 행 번호), Y축 열(여러 개), 종류(선·점·막대=마지막 값)를 고릅니다. 개요에서 Run을 고르면 그 Run들만, 아니면 그 파일이 있는 Run(최대 8개)을 겹쳐 그립니다.
점이 2000개를 넘으면 고르게 뽑은 표본만 그리고 그렇다고 표시합니다. 아래 통계(개수·최소·최대·평균·표준편차·마지막·빠진 칸)는 전체 데이터로 계산합니다. Y 단위가 섞이면 경고합니다.

## 6. 비교와 AI 분석
개요에서 Run을 두 개 이상 고르고 **고른 Run 비교**. 파라미터·커밋·환경·상태·시간·지표·결과 파일을 나란히 보이고, Run마다 다른 조건은 노랗게 표시합니다.
▲·▼는 단위가 같은 지표의 가장 큰·작은 값입니다(좋고 나쁨은 직접 판단하세요).

**AI 분석**의 버튼(결과 요약·Run 비교 해석·실패·이상 찾기·다음 실험 제안) 또는 직접 쓴 질문을 누르면, 고른 Run의 기록만 채팅에 첨부되고 채팅 화면으로 갑니다.
보내기 전에 첨부와 질문을 확인하세요. 질문에는 '기록에 없는 값은 지어내지 말 것, 관찰과 해석을 나눌 것, 상관관계를 인과로 단정하지 말 것, Run ID를 근거로 달 것,
실험을 직접 실행하지 말 것'이 붙습니다. AI가 제안한 실험은 사용자가 Lab에서 직접 설정하고 승인해야 실행됩니다.

**프로젝트 기억에 남기기**: 고른 요약을 이 작업 폴더의 프로젝트 기억에 저장합니다(설정 → 기억에서 보고 지울 수 있음). 자동으로 남기지 않습니다.

## 7. 지우기
- Run·실험의 **기록 지우기**는 Lab 기록과 Lab이 따로 둔 사본(실행한 노트북·변경 패치)만 지웁니다. 작업 폴더의 코드·결과 파일은 그대로입니다.
- 실행 중인 Run은 지울 수 없습니다(먼저 멈추기).
