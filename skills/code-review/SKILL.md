# 코드 리뷰 스킬

## 절차
1. 검토 대상 파일을 read로 모두 읽는다. 대상이 정해지지 않았으면 list와 search로 관련 파일을 찾는다.
2. 함수가 호출되는 곳과 설정 파일처럼 필요한 맥락이 있으면 search로 확인한다. 추측으로 판단하지 않는다.
3. 아래 순서로 문제를 찾는다.
   - 버그: 잘못된 로직, 경계 조건, 예외 처리 누락, 자원 누수
   - 보안: 입력 검증, 비밀 정보 노출, 위험한 명령 실행
   - 유지보수: 중복, 지나친 복잡도, 이해하기 어려운 이름
4. 테스트나 실행 방법이 있으면 run으로 확인해 본다.
5. 사용자가 고쳐 달라고 할 때만 edit로 수정한다. 검토만 요청했으면 파일을 바꾸지 않는다.

## 출력 형식
- 심각한 것부터 정리하고, 항목마다 `파일:줄`, 문제, 왜 문제인지, 고치는 방법을 적는다
- 문제가 없으면 없다고 짧게 말한다. 억지로 지적거리를 만들지 않는다
