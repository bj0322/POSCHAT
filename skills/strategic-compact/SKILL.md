# 전략적 맥락 요약

긴 작업에서 조사, 계획, 구현, 검증 등 단계가 바뀔 때 대화 맥락이 커졌다면 요약을 고려한다. 작업 중인 세부 사항이 필요한 구현 도중에는 서둘러 요약하지 않는다.

- 조사에서 계획으로 넘어갈 때는 근거와 결정, 남은 의문을 정리한다.
- 계획에서 구현으로 넘어갈 때는 목표, 제약, 수정할 파일과 다음 단계를 보존한다.
- 구현에서 검증으로 넘어갈 때는 최근 변경 내용이 필요한지 먼저 살핀다.
- 실패한 접근이나 별개의 작업으로 전환할 때는 실패 원인과 남은 일을 남긴다.

POSCHAT Code의 작업 탭에서는 작업이 멈춰 있을 때 사용자가 `/compact`를 실행해 지난 지시와 답을 요약할 수 있다. 요약은 세부 대화의 손실을 수반하므로 중요한 사용자 요구, 결정, 수정 파일, 시험 결과와 남은 일은 먼저 확인한다. 필요한 경우 사용자의 작업 공간에 기록하기 전에 그 공간의 권한과 지침을 따른다.

이 스킬은 요약 시점을 판단하는 안내다. 컨텍스트 크기를 자동 측정하거나 ECC의 훅을 실행하지 않는다. 자동 요약이나 토큰 절감 효과를 보장하지 않는다.
